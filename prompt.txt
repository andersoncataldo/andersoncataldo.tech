SECAO 2 — BUGS E PROBLEMAS TECNICOS IDENTIFICADOS
================================================================================

BUG-01: Foto nao convertida para WebP — performance critica
  Arquivo: /src/assets/anderson-cataldo.jpeg (94 KB)
  Problema: JPEG sem otimizacao. Nenhuma diretiva de conversao para WebP.
            O Vite nao converte automaticamente sem plugin.
  Impacto: LCP (Largest Contentful Paint) mais lento; piora o PageSpeed Score.
  Correcao: Converter anderson-cataldo.jpeg para anderson-cataldo.webp (qualidade
            85%). Atualizar os imports em About.tsx e Sidebar.tsx para o arquivo .webp.
            Manter fallback JPEG se necessario via picture element.

BUG-02: Duplicacao da informacao "6 semestre" na Hero
  Arquivo: /src/components/Hero.tsx (linhas 53 e 71)
  Problema: "6 semestre em Ciencia da Computacao" aparece no card de "Formacao"
            (linha 53) e novamente como pill "6 semestre" no bloco de pills
            abaixo (linha 71). Mesma informacao repetida em visual diferente
            na mesma secao.
  Correcao: Remover ou substituir o pill redundante "6 semestre" da linha 71
            por algo mais informativo como "Fortaleza, CE" ou "2 anos de exp."

BUG-03: key={index} em listas mapeadas — anti-pattern React
  Arquivos:
    Experience.tsx linha 79  — key={index} em experiences.map()
    Projects.tsx linha 75    — key={index} em projects.map()
    Skills.tsx linha 60      — key={index} em skillGroups.map()
    Skills.tsx linha 74      — key={i} em group.skills.map()
    Skills.tsx linha 103     — key={i} em softSkills.map()
  Problema: Usar index como key pode causar problemas de reconciliacao do React,
            especialmente se a ordem dos itens mudar. E um code smell reconhecido.
  Correcao: Para skills estaticas, usar o proprio nome como key (sao unicos).
            Para Experience e Project, usar title/company como key.

BUG-04: vite.config.ts com comentario de migracao esquecido
  Arquivo: /vite.config.ts linha 2
  Problema: Ha um comentario "// <--- Mude aqui (tire o '-oxc')" que e um
            artefato de desenvolvimento. Nao deve existir em producao.
  Correcao: Remover o comentario, deixar apenas o import limpo.

BUG-05: package.json com nome generico "vite-react"
  Arquivo: /package.json linha 2
  Problema: "name": "vite-react" e o nome padrao do template Vite.
  Correcao: Mudar para "name": "andersoncataldo-tech" e adicionar campos:
            "version": "1.0.0", "author": "Anderson Cataldo",
            "description": "Portfolio profissional de Anderson Cataldo"

BUG-06: aria-labelledby sem correspondencia em Skills
  Arquivo: /src/components/Skills.tsx linha 71 e linha 102
  Problema:
    - Linha 71: aria-labelledby aponta para id que nao existe no elemento h3.
    - Linha 102: aria-labelledby="soft-skills-title" sem elemento correspondente.
  Correcao:
    - No h3 de cada grupo, adicionar id={"skill-group-" + index}.
    - No h4 "Mindset Profissional", adicionar id="soft-skills-title".

BUG-07: Open Graph image usando favicon.svg — inadequado para compartilhamento
  Arquivo: /index.html linhas 25 e 31
  Problema: og:image e twitter:image apontam para /favicon.svg.
            Redes sociais nao renderizam SVG para preview.
  Correcao: Criar /public/og-image.png (1200x630px) com nome e cargo do Anderson.
            Atualizar as meta tags para apontar para a URL publica da imagem.

BUG-08: Sidebar colapsada nao mostra icones de links externos
  Arquivo: /src/components/Sidebar.tsx linha 221
  Problema: Ao colapsar, os icones de GitHub/LinkedIn somem completamente.
            Deveriam mostrar apenas os icones (sem texto), consistente com navLinks.
  Correcao: Quando collapsed, mostrar os icones de externalLinks sem texto.

BUG-09: SectionLoader usa classe border-apple-accent nao definida no CSS
  Arquivo: /src/App.tsx linha 17
  Problema: "border-apple-accent" nao esta definida em index.css.
            Apenas bg-apple-accent e text-apple-accent estao mapeadas.
  Correcao: Adicionar em index.css:
            .border-apple-accent { border-color: var(--color-apple-blue); }

BUG-10: Sem preload da foto principal
  Arquivo: /index.html
  Problema: A foto do Anderson nao tem preload. O navegador so a descobre
            quando o JS processa o componente, atrasando o LCP.
  Correcao: Adicionar no head do index.html:
            <link rel="preload" as="image" href="/anderson-cataldo.webp" />
            (apos converter para WebP conforme BUG-01).

SECAO 3 — O QUE ESTA FALTANDO (adicionar ao portfolio)
================================================================================

FALTA-01: Secao de metricas quantitativas / numeros de impacto
  Por que: Frases como "reduzindo checagens manuais" sao vagas. Recrutadores e
           empresas de tech valorizam impacto mensuravel.
  O que fazer: Adicionar um bloco visual de "Numeros" entre o Hero e o About
               (ou como cards no Hero) com dados reais:
               - Exemplo: "200+ horas automatizadas", "3 sistemas em producao",
                 "2 empresas de grande porte", etc.
  Alternativa: Substituir os 3 cards de contexto do Hero (Formacao, Experiencia,
               Diferencial) por cards de metricas com numero grande em destaque.

FALTA-02: Botao de CTA principal no Hero
  Por que: A secao Hero nao tem um Call-To-Action claro. O visitante nao sabe
           o que fazer depois de ler o headline.
  O que fazer: Adicionar abaixo dos cards, dois botoes:
    [Ver Projetos] — scroll para #projetos (primario, bg-apple-accent, text-white)
    [Entrar em Contato] — scroll para #contato (secundario, outlined)
  Implementar scrollToSection via ancoras HTML simples ou usando a funcao
  scrollToSection ja existente no Sidebar.tsx como referencia.

FALTA-03: Preview/screenshot dos projetos
  Por que: A secao Projects usa apenas icones genericos (Layout, BookOpen).
           Recrutadores tecnicos querem ver o produto visual.
  O que fazer: Para o projeto "Sao Carlo Acutis", adicionar um screenshot real.
               Para o "Portfolio Web", um screenshot do proprio site.
               Usar o campo images?: string[] ja existente na interface Project.
               Renderizar uma imagem preview no topo do card de projeto.

FALTA-04: Secao de idiomas
  Por que: Para empresas internacionais, conhecer o nivel de ingles e fundamental.
  O que fazer: Adicionar no componente About.tsx ou Skills.tsx um card "Idiomas":
    - Portugues: Nativo
    - Ingles: [nivel real — Intermediario/Avancado/Fluente]
  Usar icone Globe da lucide-react.

FALTA-05: Disponibilidade e modalidade de trabalho
  Por que: Empresas precisam saber se o candidato aceita remoto, hibrido, presencial.
  O que fazer: No About.tsx, no card de "Localizacao", expandir o texto para:
               "Fortaleza, CE — disponivel para remoto e hibrido"

FALTA-06: Error boundary para componentes lazy
  Arquivo: /src/App.tsx
  Por que: Se qualquer chunk lazy falhar (usuario offline, CDN down), a aplicacao
           mostrara tela em branco sem feedback.
  O que fazer: Criar ErrorBoundary.tsx simples e envolver cada Suspense:
               <ErrorBoundary fallback={<SectionError />}>
                 <Suspense fallback={<SectionLoader />}>
                   <About />
                 </Suspense>
               </ErrorBoundary>
  Referencia de implementacao de ErrorBoundary com React class component ou
  usar biblioteca react-error-boundary se preferir.

FALTA-07: Meta tag theme-color para mobile
  Arquivo: /index.html
  O que fazer: Adicionar no head:
    <meta name="theme-color" content="#7c3aed" media="(prefers-color-scheme: light)" />
    <meta name="theme-color" content="#1e1b4b" media="(prefers-color-scheme: dark)" />

FALTA-08: Link canonico no HTML
  Arquivo: /index.html
  O que fazer: Adicionar no head:
    <link rel="canonical" href="https://andersoncataldo.tech" />
    (ou URL de producao atual)

FALTA-09: Badge visual "Atual" nas experiencias ativas
  Arquivo: /src/components/Experience.tsx
  O que fazer: No item de experiencia com periodo "Atual", mostrar um badge
               verde com texto "Em andamento" ou um dot verde animado ao lado
               do periodo para destacar visualmente o emprego atual vs anterior.

FALTA-10: Link "Ver codigo" com label visivel nos cards de Projects
  Arquivo: /src/components/Projects.tsx
  O que fazer: Ao lado do icone do GitHub, adicionar texto "Ver codigo" pequeno
               que aparece no hover, ou tornar o link mais evidente visualmente.

SECAO 7 — CONTEXTO ADICIONAL PARA A IA QUE IRA IMPLEMENTAR
================================================================================

1. NAO alterar o design system atual (cores, fontes, espacamentos). O visual
   "Apple-inspired" com sidebar azul/roxo (#7c3aed) e intencional e bom.

2. NAO adicionar novas dependencias desnecessarias. O projeto ja tem Framer Motion
   para animacoes — usa-lo para novos elementos animados.

3. O portfolio e 100% em portugues brasileiro. Manter esse idioma em todos os
   novos textos adicionados. Termos tecnicos (React, TypeScript, RPA) permanecem
   em ingles por serem nomes proprios de tecnologias.

4. O projeto usa Tailwind CSS v4 com @theme block (nao tailwind.config.js). Todas
   as customizacoes de design tokens ficam em /src/styles/index.css dentro de @theme.
   NAO criar tailwind.config.js.

5. Framer Motion: todos os componentes ja usam o padrao:
   - useReducedMotion() para respeitar preferencias de acessibilidade
   - whileInView com viewport={{ once: true }} para animar entrada
   - Verificar esse padrao em qualquer novo elemento animado.

6. A sidebar tem dois estados em desktop: expanded (w-72) e collapsed (w-20).
   Qualquer conteudo adicionado a sidebar deve respeitar o estado collapsed,
   mostrando apenas icone sem texto quando collapsed.

7. Assets: Qualquer nova imagem deve ser adicionada em /src/assets/ e importada
   via ES module import. Nao usar URLs hardcoded para assets locais.

8. O curriculo PDF esta em /src/assets/curriculo-anderson-pt-br.pdf e e importado
   com import resumeFile from '../assets/curriculo-anderson-pt-br.pdf'

9. Acessibilidade: O projeto tem bom suporte a a11y (skip link, aria-labels,
   role="dialog" no mobile drawer, aria-live no CopyEmail). Manter esse nivel
   e corrigir os bugs de aria identificados na Secao 2.
